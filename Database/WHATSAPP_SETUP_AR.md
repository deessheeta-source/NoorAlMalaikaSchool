# إعداد وحدة واتساب

## قبل التفعيل

1. خذ نسخة احتياطية `.bak` من قاعدة البيانات.
2. نفّذ `Migrations/20261015_AddWhatsAppModule.sql` مرة واحدة على قاعدة التطبيق، ثم نفّذ `Migrations/20261016_EnhanceWhatsAppModule.sql` بعده، ثم `Migrations/20261022_WhatsAppP0Hardening.sql`، ثم `Migrations/20261023_WhatsAppMessageFormatting.sql`، ثم `Migrations/20261023_AddSystemSettings.sql`، وأخيراً `Migrations/20261025_WhatsAppDeliverySafety.sql`. كلها آمنة للتكرار (idempotent). لا تعمل الوحدة قبل تطبيق الملفات؛ ستظهر على الصفحة رسالة تطلب تجهيز الجداول. عند استخدام `sqlcmd` مع ملف يحتوي عربية أضف `-f 65001`.
3. جهّز WhatsApp Business Platform / Cloud API لدى Meta ورقم الإرسال واسمح باستخدام بيانات أولياء الأمور وفق موافقتهم. (غير مطلوب إذا اخترت وضع الإرسال اليدوي المجاني أدناه.)
4. **الإعدادات غير السرية** لها قيم افتراضية في `Web.config` داخل `<appSettings>`، ويمكن لمدير النظام تعديلها من تبويب **الإعدادات** في صفحة واتساب. تُحفظ القيم المعدّلة في جدول `dbo.SystemSettings` وتنتقل مع النسخة الاحتياطية للقاعدة. ترتيب الأولوية: متغير بيئة `NOOR_WHATSAPP_*` ← جدول `SystemSettings` ← `Web.config`:

   - `WhatsAppManagerPhone` (رقم دولي لمدير النظام بعد موافقته على الاستلام، مثال: `+218944684046` — يُقبل أيضاً المحلي `0944684046` ويُحوَّل تلقائياً إلى صيغة دولية)
   - `WhatsAppDefaultCountryCode` (افتراضياً `218` للأرقام المحلية الليبية)
   - `WhatsAppReplyRequireConsent` (`true` لفرض وجود موافقة فعّالة قبل إرسال أي رد على استفسار وارد)
   - `WhatsAppManualLinks` (`true` لتشغيل وضع الإرسال اليدوي المجاني عبر روابط واتساب بدون Cloud API)

   **الأسرار وإعدادات الخادم** تُضاف إلى **متغيرات بيئة عملية IIS** أو مخزن أسرار الخادم، ولا تُحفظ في قاعدة البيانات أو `Web.config` أو المستودع:

   - `NOOR_WHATSAPP_ACCESS_TOKEN`
   - `NOOR_WHATSAPP_PHONE_NUMBER_ID`
   - `NOOR_WHATSAPP_GRAPH_VERSION` (إصدار Graph API مدعوم في حساب Meta)
   - `NOOR_WHATSAPP_APP_SECRET` (للتحقق من توقيع Webhook)
   - `NOOR_WHATSAPP_WEBHOOK_VERIFY_TOKEN` (قيمة عشوائية طويلة يختارها مسؤول النظام)
   - `NOOR_WHATSAPP_DISPATCH_KEY` (مفتاح سري لاستدعاء معالج الرسائل المجدولة)
   - NOOR_WHATSAPP_DISPATCH_URL (عنوان HTTPS الكامل، أو عنوان HTTP المحلي على 127.0.0.1 فقط، المنتهي بـ /Pages/WhatsApp/Dispatch.ashx)

   > تستخدم إعدادات الوحدة متغيرات البيئة قبل إعدادات النظام وWeb.config حيث يدعم الإعداد ذلك. معالج Dispatch.ashx يقرأ مفتاحه من متغير بيئة على مستوى الجهاز فقط؛ يجب أن يكون NOOR_WHATSAPP_DISPATCH_KEY بطول 32 محرفاً على الأقل. بعد تغيير متغيرات الجهاز أعد تدوير مجمع تطبيق IIS كي يلتقط العامل القيم الجديدة. إذا استخدمت HTTP، اربط الموقع على 127.0.0.1 فقط ولا تستخدم عنوان الشبكة؛ يظل Webhook لدى Meta بحاجة إلى HTTPS عام.

5. للوضع الآلي عبر Cloud API فقط: سجّل عنوان HTTPS التالي في إعدادات Webhooks لتطبيق Meta، واشترك في حقل `messages`:
   `/Pages/WhatsApp/Webhook.ashx`
6. للوضع الآلي عبر Cloud API فقط: بعد ضبط متغيري الجهاز NOOR_WHATSAPP_DISPATCH_URL وNOOR_WHATSAPP_DISPATCH_KEY، والتأكد من أن العنوان يعمل عبر HTTPS بشهادة صالحة أو عبر HTTP على 127.0.0.1 فقط، افتح PowerShell كمسؤول وشغّل مرة واحدة Database/tools/Register-WhatsAppQueueTask.ps1. يتحقق السكربت من العنوان والمفتاح ويسجّل المهمة كل دقيقة كمستخدم SYSTEM، مع منع تشغيل نسختين متزامنتين.

   يرسل سكربت التشغيل ترويسة Authorization: Bearer NOOR_WHATSAPP_DISPATCH_KEY ولا يضع المفتاح في عنوان URL أو يتبع إعادة التوجيه. معالج Dispatch.ashx يرفض HTTP من أي جهاز آخر. لا تسجّل المهمة قبل تجهيز العنوان والمفتاح؛ لا ينشئها السكربت إذا كانت الإعدادات ناقصة أو إذا كانت المهمة موجودة مسبقاً. تعرض صفحة الوحدة تنبيهاً إذا لم يُضبط العنوان أو إذا تراكمت رسائل مستحقة غير معالجة.

   تابع نتيجة كل رسالة من سجل واتساب، وراجع **Task Scheduler → History** لمعرفة محاولات تشغيل المهمة. حالات النتائج غير المؤكدة لا تعاد تلقائياً؛ تحقّق من سجل Meta قبل إعادة إرسالها يدوياً.

## وضع الإرسال اليدوي (بدون رسوم)

عند عدم وجود بيانات Cloud API، أو عند ضبط `NOOR_WHATSAPP_MANUAL_LINKS=true`، يعمل النظام بلا أي رسوم ولا اشتراك:

1. تُجهَّز الرسائل (الإعلان، الغياب، الرصيد، الدرجات، دروس اليوم، ملخص المدير، أو الرد على استفسار) في تبويب **الإرسال اليدوي** بدل إرسالها آلياً.
2. لكل رسالة رابط wa.me يحمل رقم ولي الأمر والنص كاملاً ومعرّباً. افتح الرابط في واتساب، أرسل الرسالة من التطبيق، ثم ارجع واضغط **تأكيد الإرسال**. لا يستطيع الموقع اكتشاف الإرسال من داخل واتساب؛ لا تؤكد إلا بعد الإرسال فعلياً.
3. لا يحتاج هذا المسار إلى مفاتيح Cloud API أو رسوم منصة Cloud API. قد تُحسب بيانات الإنترنت وفق باقة الاتصال؛ أرسل فقط إلى أولياء الأمور ذوي الموافقة السارية.
4. القيد الوحيد: الإرسال يدوي (نقرة لكل ولي أمر)، والمحتوى النصي فقط (لا قوالب معتمدة ولا وسائط).

> تتغير أسعار Cloud API حسب بلد المستلم وفئة الرسالة. توضح [صفحة أسعار Meta الرسمية](https://whatsappbusiness.com/products/platform-pricing/) أن التسعير لكل رسالة مسلّمة، وأن رسائل الخدمة ورسائل Utility المرسلة رداً على المستخدم لا تُفرض عليها رسوم من Meta، بينما قد تُسعّر فئات أخرى. راجع الأسعار قبل تشغيل الإرسال الآلي؛ الروابط اليدوية لا تستخدم Cloud API.

## ضوابط التشغيل

- تبدأ كل رسالة صادرة بسطر **مدرسة نور الملائكة** ثم **السلام عليكم**، ويُضاف ذلك تلقائياً حتى للرسائل الحرة والردود ومن القوالب القديمة. القوالب المبدئية منسّقة على أسطر مستقلة: اسم ولي الأمر، اسم الطالب، الصف، التفاصيل، ثم خاتمة مناسبة.
- لا يدرج ولي الأمر ضمن جمهور الإرسال إلا بعد تسجيل موافقته؛ وأي إلغاء للموافقة يوقف الإرسال اللاحق.
- عند ضبط `NOOR_WHATSAPP_REPLY_REQUIRE_CONSENT=true` لا يُرسل أي رد على استفسار وارد لرقم بلا موافقة فعّالة، وتظهر سياسة الرد الحالية للمستخدم في صندوق الردود.
- تسجيل الموافقة من شاشة الموافقات يتطلب تأكيد توثيقها وكتابة مصدر التحقق؛ ويُحفظ وقت التسجيل أو الإلغاء وسببه لأغراض التدقيق.
- تُرسل الرسائل إلى أرقام أولياء الأمور كلٌ على حدة. ربط الصف في الشاشة هو قائمة مستلمين داخل النظام، وليس مجموعة واتساب فعلية.
- القوالب المبدئية محلية وغير معتمدة من Meta. لا تُرسل خارج نافذة الخدمة إلا بقالب اعتمدته Meta، مع إدخال اسمه المعتمد ولغته في سجل القالب.
- إرسال ملخص المدير يتطلب تأكيد موافقته في الشاشة؛ استخدم قالب Meta معتمداً إذا لم تكن نافذة المحادثة مفتوحة.
- في الوضع الآلي، حالة `Sent` تعني أن Meta قبلت الطلب. حالات التسليم والقراءة والفشل تصل لاحقاً عبر Webhook. وفي الوضع اليدوي، `Sent` تعني أن الموظف أكّد الإرسال.
- الجدولة في الوضع الآلي تعتمد على استدعاء `Dispatch.ashx` دورياً من مهمة مجدولة على الخادم؛ لا تعتمد على بقاء صفحة المتصفح مفتوحة.
- اضبط المنطقة الزمنية لخادم IIS على توقيت المدرسة؛ وقت الجدولة يحوّل توقيت الخادم إلى UTC قبل تخزينه.
- سجل الرسائل يحتفظ بمحتوى الرسائل الواردة والصادرة. حدّد الوصول إلى الصفحة ومدد الاحتفاظ وفق سياسة المدرسة.
