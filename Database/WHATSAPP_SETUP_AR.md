# إعداد وحدة واتساب

## قبل التفعيل

1. خذ نسخة احتياطية `.bak` من قاعدة البيانات.
2. نفّذ `Migrations/20261015_AddWhatsAppModule.sql` مرة واحدة على قاعدة التطبيق، ثم نفّذ `Migrations/20261016_EnhanceWhatsAppModule.sql` بعده. كلاهما آمن للتكرار (idempotent). لا تعمل الوحدة قبل تطبيق الملفين؛ ستظهر على الصفحة رسالة تطلب تجهيز الجداول.
3. جهّز WhatsApp Business Platform / Cloud API لدى Meta ورقم الإرسال واسمح باستخدام بيانات أولياء الأمور وفق موافقتهم. (غير مطلوب إذا اخترت وضع الإرسال اليدوي المجاني أدناه.)
4. أضف القيم التالية إلى **متغيرات بيئة عملية IIS** أو مخزن أسرار الخادم. لا تحفظ رمز الوصول في قاعدة البيانات أو في المستودع:

   - `NOOR_WHATSAPP_ACCESS_TOKEN`
   - `NOOR_WHATSAPP_PHONE_NUMBER_ID`
   - `NOOR_WHATSAPP_GRAPH_VERSION` (إصدار Graph API مدعوم في حساب Meta)
   - `NOOR_WHATSAPP_DEFAULT_COUNTRY_CODE` (افتراضياً `218` للأرقام المحلية الليبية)
   - `NOOR_WHATSAPP_MANAGER_PHONE` (رقم دولي لمدير النظام بعد موافقته على الاستلام، مثال محلي: `0925005032` — يُحوَّل تلقائياً إلى صيغة دولية وفق رمز الدولة)
   - `NOOR_WHATSAPP_APP_SECRET` (للتحقق من توقيع Webhook)
   - `NOOR_WHATSAPP_WEBHOOK_VERIFY_TOKEN` (قيمة عشوائية طويلة يختارها مسؤول النظام)
   - `NOOR_WHATSAPP_DISPATCH_KEY` (مفتاح سري لاستدعاء معالج الرسائل المجدولة)
   - `NOOR_WHATSAPP_DISPATCH_URL` (عنوان HTTPS الكامل الذي ينتهي بـ `/Pages/WhatsApp/Dispatch.ashx`)
   - `NOOR_WHATSAPP_REPLY_REQUIRE_CONSENT` (`true` لفرض وجود موافقة فعّالة قبل إرسال أي رد على استفسار وارد؛ اتركه فارغاً للاعتماد على نافذة خدمة Meta فقط)
   - `NOOR_WHATSAPP_MANUAL_LINKS` (`true` لتشغيل وضع الإرسال اليدوي المجاني عبر روابط واتساب بدون Cloud API؛ راجع القسم التالي)

5. للوضع الآلي عبر Cloud API فقط: سجّل عنوان HTTPS التالي في إعدادات Webhooks لتطبيق Meta، واشترك في حقل `messages`:
   `/Pages/WhatsApp/Webhook.ashx`
6. للوضع الآلي عبر Cloud API فقط: جدْول `Database/tools/Invoke-WhatsAppQueue.ps1`
   كل دقيقة في Windows Task Scheduler. يرسل الملف ترويسة
   `Authorization: Bearer <NOOR_WHATSAPP_DISPATCH_KEY>` ولا يضع المفتاح في عنوان URL.
   تعرض صفحة الوحدة تنبيهاً إذا لم يُضبط `NOOR_WHATSAPP_DISPATCH_URL` أو إذا تراكمت رسائل مستحقة غير معالجة.

## وضع الإرسال اليدوي (بدون رسوم)

عند عدم وجود بيانات Cloud API، أو عند ضبط `NOOR_WHATSAPP_MANUAL_LINKS=true`، يعمل النظام بلا أي رسوم ولا اشتراك:

1. تُجهَّز الرسائل (الإعلان، الغياب، الرصيد، الدرجات، دروس اليوم، ملخص المدير، أو الرد على استفسار) في تبويب **الإرسال اليدوي** بدل إرسالها آلياً.
2. لكل رسالة رابط `wa.me` يحمل رقم ولي الأمر والنص كاملاً ومعرّباً. يفتح الموظف الرابط في واتساب (ويب/سطح المكتب)، يضغط «إرسال»، ثم يعود ويضغط **تم الإرسال** ليُحدَّث السجل.
3. لا تُستخدم أي مفاتيح سرية ولا يوجد أي مبلغ؛ ويجري الإرسال من حساب واتساب الرسمي للمدرسة بالطريقة المعتادة (لا يخالف شروط واتساب ولا يعرّض الرقم لخطر الحظر).
4. القيد الوحيد: الإرسال يدوي (نقرة لكل ولي أمر)، والمحتوى النصي فقط (لا قوالب معتمدة ولا وسائط).

> ملاحظة: الوضع الآلي عبر WhatsApp Cloud API لم يعد مجانياً للرسائل الصادرة منذ 1 أكتوبر 2026 (تتضمن 1000 «رسالة خدمة» مجانية شهرياً للردّ داخل نافذة 24 ساعة فقط). لذلك يعمل وضع الروابط اليدوية بلا أي تكلفة.

## ضوابط التشغيل

- لا يدرج ولي الأمر ضمن جمهور الإرسال إلا بعد تسجيل موافقته؛ وأي إلغاء للموافقة يوقف الإرسال اللاحق.
- عند ضبط `NOOR_WHATSAPP_REPLY_REQUIRE_CONSENT=true` لا يُرسل أي رد على استفسار وارد لرقم بلا موافقة فعّالة، وتظهر سياسة الرد الحالية للمستخدم في صندوق الردود.
- تسجيل الموافقة من شاشة الموافقات يتطلب تأكيد توثيقها وكتابة مصدر التحقق؛ ويُحفظ وقت التسجيل أو الإلغاء وسببه لأغراض التدقيق.
- تُرسل الرسائل إلى أرقام أولياء الأمور كلٌ على حدة. ربط الصف في الشاشة هو قائمة مستلمين داخل النظام، وليس مجموعة واتساب فعلية.
- القوالب المبدئية محلية وغير معتمدة من Meta. لا تُرسل خارج نافذة الخدمة إلا بقالب اعتمدته Meta، مع إدخال اسمه المعتمد ولغته في سجل القالب.
- إرسال ملخص المدير يتطلب تأكيد موافقته في الشاشة؛ استخدم قالب Meta معتمداً إذا لم تكن نافذة المحادثة مفتوحة.
- في الوضع الآلي، حالة `Sent` تعني أن Meta قبلت الطلب. حالات التسليم والقراءة والفشل تصل لاحقاً عبر Webhook. وفي الوضع اليدوي، `Sent` تعني أن الموظف أكّد الإرسال.
- الجدولة في الوضع الآلي تعتمد على استدعاء `Dispatch.ashx` دورياً من مهمة مجدولة على الخادم؛ لا تعتمد على بقاء صفحة المتصفح مفتوحة.
- اضبط المنطقة الزمنية لخادم IIS على توقيت المدرسة؛ وقت الجدولة يحوّل توقيت الخادم إلى UTC قبل تخزينه.
- سجل الرسائل يحتفظ بمحتوى الرسائل الواردة والصادرة. حدّد الوصول إلى الصفحة ومدد الاحتفاظ وفق سياسة المدرسة.
